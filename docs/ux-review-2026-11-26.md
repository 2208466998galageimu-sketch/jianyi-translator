# 简译交互审查与调整方案（2026-11-26）

状态：用户于 2026-11-26 同意本审查方案及之前翻译偏好调整，已在 0.8.0 实施并生成安装包。下文保留审查时的建议措辞；最终实现、验证与边界以 [0.8.0 发布记录](release-0.8.0.md) 为准。本机安装版未自动覆盖。

审查依据：当前 0.7.0 源码、已有隔离测试截图及官方产品文档；本次未重新操作安装版，也未做真实用户可用性测试。文中“缺少”限定为检查到的当前设置页/结果浮窗，不把已有底层能力误报为不存在。

## 1. 已同意：翻译偏好调整

- 名称收拢为“翻译偏好”；默认页只呈现启用状态、已保存规则、添加规则与保存更改。
- “当前场景”自由输入不再作为日常使用前置条件；现有带场景规则保留，迁移时需明确处理范围，不得静默变为全局。
- 添加规则使用自然语言；语言范围按需展开。按实际识别语言匹配，解决 auto 与具体语言不一致导致规则失效的问题，明确识别失败时的行为。
- 示例整理、根据译文修改整理建议放入更多设置；待确认建议有内容才出现入口，确认前不进入翻译请求。
- 知识库管理术语对应关系；偏好管理句段表达与格式；候选建议独立于已启用规则。
- 约束优先级：原意与受保护内容、本次明确译法、知识库术语、表达偏好。不得用偏好授权删减、改写事实或覆盖术语。
- 翻译调整仍位于结果浮窗，点击后展开。可展开查看本次实际提供了哪些知识库和偏好；未验证采用时不得声称“已采用”。
- 先简化页面和保存行为，再补生效反馈，最后完善被动整理；不扩张为自动理解全部个人习惯。
- 首阶段个人偏好为全局基础规则，按语言筛选；如以后确需分领域，优先复用知识库组合的可选关联，不另造场景管理系统。

## 2. 全局导航建议

保留控制条和更多设置分工。控制条只承载当前使用中的开关、方向、翻译方式、框选入口；知识库组合仅在支持的 LLM 路径提供快捷切换。配置、管理进入更多设置。

更多设置保留侧边两级导航，建议分组：

```text
翻译设置
  语言与翻译方式
  取词与识图
  结果显示
  翻译偏好
知识库
  知识库管理
  知识库组合
  导入与生成
  已删除内容
模型配置
  翻译模型
  OCR 模型
  导入助手模型
数据与存储
  下载与存储
  备份与恢复
帮助与关于（底部）
```

这是职责归属建议，不要求每个子项都立刻新建页面；单一设置可先用同页分组。现有结果显示时长迁入结果显示，保留 10/50、90/300/600 默认值及恢复默认，不改变已确认的框选生命周期。知识库导入和生成放在同页两个明确任务入口，不增加顶层模式。

## 3. 模块审查与建议

### 3.1 控制条、取词和翻译结果

现有：总开关、直译/通序、呈现方式、框选按钮、自动 OCR 开关、结果关闭、OCR 原文校对、LLM 调整与撤销。

观察：结果浮窗没有显式复制译文按钮；调整面板同时展开术语选择和整段编辑；浮窗缺少直接重试入口；语言/翻译来源/知识库状态分散。长内容固定较小视口和嵌套滚动需评估。

建议：常驻面板底部仅保留复制、调整、更多，失败时原位提供重试或直达正确设置；调整内部按术语替换/修改译文再展开。只读点击穿透悬注不放按钮。状态依次显示读取、识别、翻译、完成，取消不作为故障。OCR 低识别置信仅表示识别风险，不代表译文正确率。长内容优先一个主滚动区。

框选结果仍在菜单下方单实例替换，不因外部点击、切换应用、原窗口事件、外部滚轮关闭；保留现有按内容计时、交互暂停和新框选替换。不得借鉴案例时恢复已移除热键。

### 3.2 模型配置

现有：翻译/OCR/助手独立入口；本地 MT、本机 LLM、API；已配置、推荐、导入、系统文件选择器、帮助、下载取消、校验、试运行成功后启用、删除配置、下载位置选择。

观察：摘要“已就绪”依据配置存在/当前选择，不能代表当前实时可用；已安装列表缺少直接编辑配置操作；API 地址和模型名依赖手填；三页重复突出同一下载目录；OCR 推荐主要展示型号名；模型 iframe 与知识库页面使用独立宽度和控件样式。连接测试是固定短句，未证明助手 JSON 任务能力。

建议：三页统一当前使用、切换已有、添加模型的顺序；添加再分推荐/导入/服务连接。翻译方式先区分本地翻译与 LLM，LLM 再区分本机/远程，避免把用途与部署位置当成同一级概念。

状态分开：已保存、已安装、上次检测通过、检测失败、使用中。不得以静态配置存在冒充实时正常。API 选择服务商后给可编辑地址默认值，支持时读取模型列表，始终保留手填；显示实际请求地址、凭据已保存状态，测试结果在字段附近保留原因与纠正入口。修改配置走草稿，测试成功再提交，失败沿用原配置。

助手独立设置和凭据，不随翻译模型切换；只测试其实际所需结构化输出能力，不把简单短句测试当成全部任务可用。模型管理明确“移除配置”和“删除简译管理的模型文件”，自备外部文件默认保留；共享核心、被其他配置引用的文件不得直接删除。

推荐项显示语言覆盖、下载量/磁盘占用、资源需求与已验证适用场景；无质量评测不标“准确率更高”。本地 MT 主界面继续只展示语言与离线包，不突出内部模型名。共享 M2M 核心约 473 MiB，勾选语言不是按语言切开权重下载。

### 3.3 下载与存储

现有：目录可改、默认安装目录下 data/models；下载有进度字符串、取消，部分文件有可恢复下载能力。

观察：无全局持续可见任务入口；更改目录只影响后续下载，不搬迁已安装文件；没有面向用户的统一磁盘占用和可清理内容页。

建议：先实现一个进行中任务的全局条，切页可见，分下载/校验/试运行/启用阶段，失败保留重试和原因，不先做复杂多任务队列。展示剩余下载量、预计新增空间；共享文件避免重复计算。目录管理集中在下载与存储，模型页保留简短入口。更改后续下载位置与迁移已有模型分开，迁移需校验成功后才提交路径，不先删旧文件。管理范围和外部目录明确。

### 3.4 知识库管理和组合

现有：语言分类、库列表、词条搜索、词条新增/编辑/停用、组合勾选与全选、手动/频率顺序、显式保存、版本快照、库/组合批量删除及回收恢复。

观察：缺少词条批量启停/删除与导出入口；词条列表来源、备注、状态挤在同一列；没有库名搜索；组合只有下拉选择，当前正在生效和正在编辑的区别不够突出。版本记录显示动作/数量/时间，无逐条变更比较；回收站缺少搜索、批量恢复入口。

建议：保留库列表+词条主表两栏；详细来源、备注按选中行在抽屉呈现，窄窗口改弹层。顶栏固定搜索、新增、导入、更多；勾选后出现批量操作条。导出 UTF-8 CSV/TSV，保留语言方向/来源和必要标识。

组合先显示组合列表（当前使用、包含库数），进入后编辑成员；保存与启用含义明确，仍保留每个组合修改后保存才生效的已确认行为。频率排序可见但不等于正确率，保留手动优先级。删除组合不删除知识库。术语冲突只在实际重合原词/方向时提示，选择仍在翻译结果浮窗发生。

版本记录保持悬浮页，增加本次新增/修改/删除差异，恢复前展示影响，恢复本身生成新版本。回收站继续保留组合恢复可选恢复已删除库、默认全选、全选框、彻底删除后不虚构恢复的既有规则；新增搜索和批量恢复是本次建议。

### 3.5 导入与生成

现有：选择任务、输入、核对保存的分步流程；CSV/TSV、双语文档整理、主题/详情生成、语言建议、行级方向选择、选择所需行、版本记录。

观察：当前预览仅能改方向，不能直接修订原词/译法；已存在同方向原词被标问题，没有跳过/更新策略；无法清晰对比原有译法和新译法。模型包导入助手配置后可返回重试，相关上下文机制可复用。

建议：保留三步，不另加大型向导。预览增加新增/重复/冲突/待核对统计与过滤；可直接编辑原词译法、批量指定语言、勾选合法行。重复同译法默认跳过；不同译法默认保留原条目，用户明确选择更新后才改变并记录版本。双向语言库允许两方向数据，不能仅凭双向箭头承诺任意术语反向都成立。

文件整理和知识生成任务严格区分：整理不能凭空补译法；生成始终是待核对候选，模型产出不等于权威来源。无可用助手时保留文件与草稿并提供返回入口，不反复要求重选。只在支持范围内调用助手，不能改变模型权重语义或假装任意格式都可转换。

### 3.6 结果显示和数据保护

结果显示时长现有两组表单可保留。建议展示派生范围：1–10、11–50、51+；时间用可理解的分/秒输入但内部保持秒。当前长度计数对中日韩按字符近似计算，不应把所有情况都写作严格词数。恢复默认先改变草稿，保存后生效。

知识库版本快照不是整套用户数据备份。建议补独立备份/恢复：库、组合、偏好、必要设置；API Key 不默认导出。恢复先校验与预览并生成恢复点，模型权重默认不打入小型数据备份，不把旧路径和凭据静默视为可用。

## 4. 统一交互契约

- 页面级表单使用草稿、保存、取消；切换/关闭遇到修改提示保存、放弃、继续编辑。明确的即时开关可直接持久化，不混用隐藏的保存时机。
- 成功用短 toast；需纠正的错误在相应字段/任务卡保留；不可逆删除及已有隐私确认维持对话框，不用 toast 代替。
- 主操作每个任务区一个；低频更名、导出、版本和删除放更多菜单；批量选择采用含半选态的复选框，显示已选数量及全选范围。
- 模型页与知识库页统一内容宽度、字体、间距、按钮和状态色。不要靠缩小所有文字容纳更多选项。
- 键盘焦点、标签、禁用原因、缩放/窄窗口均需可用。整页拖动保留当前用户约定；后续若要拖拽排序，必须避开现有拖窗手势。
- 不新增解释性长段落常驻页面；需要的格式说明放现有帮助入口，状态文字直接说明事实。

## 5. 实现职责与顺序建议

继续复用 WPF + WebView2、现有 SQLite、凭据管理和模型运行组件，不换框架、不引入新数据库/向量检索。按触及的页面逐步统一 UI；模型 iframe 的独立样式和嵌入字符串只在相关改动时整理，不为审查大规模重构。

职责：页面负责草稿和呈现；原生操作层负责导入/模型/下载的检查与提交；存储负责版本、引用和恢复；翻译编排负责本次语言、模型、知识库、偏好快照。下载已有取消/校验/试运行流程应保留，先补共享状态呈现，不另造调度系统。

优先级建议：
1. 翻译主流程：常驻结果复制/重试、明确语言与实际来源；模型字段校验、可靠状态、API 编辑与测试。
2. 知识维护：可编辑导入预览、重复/冲突处理、词条批量管理、导出；同步实施已同意的偏好简化。
3. 全局一致性：导航归属、保存退出保护、模型与知识库样式统一、单任务全局进度。
4. 数据安全与效率：备份恢复、版本差异、存储占用/迁移、回收站检索/批量恢复。

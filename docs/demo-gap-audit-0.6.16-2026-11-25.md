# 简译 0.6.16 与确认 Demo 的差异核对

日期：2026-11-25。本轮仅核对原型、设计记录、源码与已安装版本，没有修改产品功能、下载模型或重新执行完整实机验收。

## 结论

0.6.16 不是确认 Demo 的完整落地版。知识库管理主体和更多设置导航大体保留；模型配置页更换为接真实后端的简化实现，本地多语言离线包、完整导入闭环和多套 OCR 推荐尚未兑现。此前确认的结果浮窗调整译法、长期翻译偏好也未落地。

已安装程序为 0.6.16.0，App DLL 与 dist/0.6.16-compact 发布构建哈希一致。

## 比较基准

- 最终整合原型：jianyi-integrated-demo.html，2026-11-24。使用最终侧栏导航及其内嵌模型页，不把早期独立模型首页强行算作最终要求。
- 模型确认稿：jianyi-model-config-language-frozen-2026-11-24.html。
- 离线语言方案：jianyi-offline-language-import-plan.md。
- 个人偏好与组合方案：jianyi-knowledge-preferences-and-presets-plan.md。
- 正式页：src/Thanslator.App/Settings/more-settings.html；原生处理：MoreSettingsWindow.cs；实际翻译：App.xaml.cs、OverlayWindow.xaml/.cs。

前四份确认稿保存在本次聊天的 visualizations 目录，已逐项读取。Demo 中模拟进度、模拟下载和示例目录不构成真实模型能力或可分发模型的证明。

## 一、最终 Demo 的直接差异

| 项目 | 已确认 Demo / 方案 | 0.6.16 实际情况 | 结论 |
|---|---|---|---|
| 常用语言离线翻译 | 中、英、日、韩、法、德、西，按需勾选；默认中英，任意已支持语言之间按实际方向清单选择 | 本地 MT 固定英语 → 简体中文；本地语言表单只有这一行，推荐区为“语言包尚未发布” | 核心缺失，连中英双向也未完成 |
| 双向/多向包与增量下载 | 一个双向或多向包；已安装方向、已选语言和核心复用；成功后自动配置 | 只有旧式单模型路径，没有多语言包清单驱动的安装登记、方向切换、共享核心增量下载 | 未实现 |
| 导入包规范 | ZIP manifest 声明格式、架构、来源、许可、语言方向；识别可受支持转换的 Transformers 模型目录 | LocalMtModelInstaller 校验五个固定 Marian/CT2 文件；manifest 可作为附带文件，但没有解析方向/架构/版本来驱动能力；不接 Safetensors 转换 | 只支持旧规范，不能把改名/移动文件当作模型转换 |
| OCR 推荐与自备模型 | 四个示例档位，下载并配置；能识别受支持的 OCR 文件布局 | 推荐区只有随安装包的 OCR 组件“启用”，没有四套真实下载目录；自备导入要求带 Jianyi.OcrHost.exe 的完整组件 ZIP | 推荐下载未实现，导入范围比 Demo 窄。四个示例名称也不能当作已经核验存在的上游产品 |
| 通用导入助手 | 本地翻译、LLM、OCR 各先直接检查，再对受支持的布局/封装问题提供助手重试；原始功能不变 | 只有本地 MT ZIP 的 InvalidDataException 路径会调用 RepairMtLayoutAsync；GGUF 和 OCR 导入失败没有接入助手修复；不具备通用转换器 | 仅局部接入 |
| 导入中途配置助手的返回闭环 | 保留待导入文件和导入上下文，配置助手后返回原位置，“修正并重试” | 快捷跳转入口存在，但模型页没有 pendingImport/importContext/returnToImport；原生失败后只保留局部变量，重新导入需要再次选文件 | 入口存在，闭环缺失 |
| 本机 LLM ZIP 导入 | 原型接受 GGUF，或包含单个 GGUF 的 ZIP，并可处理支持的封装问题 | 系统选择器只接受 .gguf，走 Ollama blob/create；不接受 GGUF ZIP | 支持范围缩水 |

主要依据：MoreSettingsWindow.cs 的 languages、ImportModelAsync、ImportGgufAsync、RepairMtLayoutAsync；LocalMtModelInstaller.cs 的 RequiredFiles/VerifyDirectory；正式模型 iframe 的 downloads、languageForm、importView 和 helper 导航。

## 二、知识库已接入，但需要明确的限制

- CSV/TSV、方向识别、可修改预览、主题和详情输入、双向 allowed_pairs、生成规则提交、快捷创建目标库均有实现。语言识别和生成已接真实模型请求，不再使用 Demo 的语言猜测函数。但本轮没有用真实模型验证质量，不能由协议夹具通过推导出生成内容准确。
- TXT/Markdown/DOCX/XLSX 双语资料整理仅允许本机导入助手；远程助手可识别词条语言、主动生成及整理受支持的 MT 文件布局，不能用于这条文档正文转换路径。不能概括成“导入助手所有任务都同时支持云端和本机”。
- 频率排序、手动顺序、个人常用词库兜底已接入真实数据。当前 MatchAsync 每次匹配到候选即增加次数，没有请求去重标识；失败重试、同一请求重复进入匹配路径是否重复计数尚需补验。此前方案要求重试和缓存重显不加分，不能把现有计数视为这部分已经完全符合。
- 个人常用词库目前是可标记的术语库；它不是“长期表达/版式习惯规则”。

## 三、此前确认、但最终设置 Demo 没有完整呈现的功能

### 译文浮窗的“调整翻译”

确认方案：只在翻译后的可交互浮窗中显示按钮；点击后出现候选；从当前组合的真实知识库译法选择；默认仅本次使用，可设为此组合首选；必要时只重译所在句并可撤销。

实际：OverlayWindow 只有译文、术语来源展开和 OCR 原文校对。ShowKnowledge 显示已按优先级选中的译法及冲突提示，没有候选交互、临时覆盖、组合术语首选保存及撤销链路。设置页没有错误地恢复“翻译试用”区，但浮窗端也尚未补上。

### 长期个人翻译偏好

确认方案：句段的表达与版式规则、主动从示例提取；可选基于用户确认修改的候选收集、去重、跨日阈值和人工确认，确认后才影响翻译。

实际：没有上述规则结构、设置页、编辑反馈入口和注入翻译请求的实现。不能把 personal=true 的普通词库当成该功能完成。这是此前方案待办，不应冒充最终 Demo 已有完整交互。

## 四、已经基本对应的部分

- 侧栏一级/二级排布：个人知识库、模型配置、框选翻译及其子页。
- 知识库语言对/综合分类、命名、个人库标记、单条增改停用、搜索备注。
- 组合修改草稿与保存、手动或频率排序、批量删除和复选框全选。
- 知识库/组合的已删除内容、引用提示、选择性恢复关联库、彻底删除清理引用。
- 词条版本记录的浮窗展示和恢复。实现为 SQLite 中的词条快照；没有使用 Git，但恢复目的已覆盖，不属于缺失项。
- 知识库助手的渐进流程、预览确认后保存版本。
- 翻译模型与导入助手模型配置分开，API 凭据走 Windows 凭据管理器。
- 四个 Qwen2.5 规格的本机下载与下载后连接检查路径；不代表四个规格都做过真实模型测试。
- 已配置模型复选与删除配置；模型原文件保留。
- 译文预览与演示填充按钮已去除；正式版初始空库属于不携带 Demo 样例数据，不是知识库功能丢失。
- 下载位置默认位于简译目录下，支持更改和恢复默认。
- 框选结果显示时长分组，10/50 词和 90/300/600 秒，保存及恢复默认。
- 后续确认的圆角窗口与整页拖动，属于正式版后加要求，不应当作偏离 Demo。

## 五、建议补齐顺序

1. 先实现真实中英双向包、统一清单和方向登记；随后验证多语言核心及其实际可用方向，再开放七语言推荐。不能先放开按钮而仍调用英译中后端。
2. 补导入上下文保存与返回重试；把安全且受支持的修正接入 MT、GGUF ZIP 和 OCR，对不支持的架构明确失败。
3. 给 OCR 建立实际可下载、可校验、可试运行的组件目录，再落实推荐档位。
4. 在实际译文浮窗补“调整翻译”和组合内的术语首选。
5. 独立实现长期翻译偏好；完善请求计数去重；补真实模型及跨屏交互验收。

本报告未把模拟模型目录、未来词频分级、向量检索或云同步当作已完成的功能，也不把已有 38 项设置工作流通过解释为整个 Demo 验收通过。

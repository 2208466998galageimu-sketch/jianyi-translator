# Thanslator dictionary data (`dict-en-zh.sqlite`)

Offline English to Simplified Chinese dictionary used by Thanslator's local
dictionary lookup (M2). This directory contains the built data artifact, its
build metadata, and the builder that produces it from ECDICT.

## Schema (`schema_version` 1)

```sql
CREATE TABLE entries (
    word TEXT PRIMARY KEY,
    word_lower TEXT NOT NULL,
    phonetic TEXT,
    translation TEXT NOT NULL,
    bnc INTEGER,
    frq INTEGER,
    collins INTEGER,
    oxford INTEGER,
    exchange TEXT
);
CREATE INDEX idx_entries_lower ON entries(word_lower);

CREATE TABLE forms (
    form TEXT PRIMARY KEY,
    word TEXT NOT NULL
);
CREATE INDEX idx_forms_word ON forms(word);

CREATE TABLE meta (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
```

Notes:

- `entries` contains all 770,611 ECDICT rows, including 373 rows whose
  translation is an empty string. `translation` is ECDICT's raw translation
  field. Line breaks are stored as the literal two characters backslash + `n`,
  exactly as they appear in the CSV; they are not converted to LF.
- `word_lower` is Python `str.lower()` of `word`. It has a non-unique index for
  case-insensitive lookup; the source snapshot happens to contain no
  case-insensitive duplicates.
- Empty optional CSV fields are stored as SQL `NULL` (`phonetic`, `exchange`,
  `collins`, `oxford`). `bnc` and `frq` are always present integers in ECDICT;
  the value `0` means "not ranked" and is preserved.
- `forms` maps an inflected surface form to a lemma that exists in `entries`.
  It is built from the `exchange` field: explicit `0:<lemma>` declarations and
  the form tags `p` (past), `d` (past participle), `i` (-ing), `3` (third
  person singular), `r` (comparative), `t` (superlative), `s` (plural), and `f`
  (compound plural). Empty tokens and self-referential form tokens are skipped;
  form tokens on entries that are already inflected are kept as lower-priority
  candidates. Conflicts are resolved deterministically: explicit
  `0:<lemma>` first, then form tokens from lemma entries, then form tokens from
  inflected entries; ties go to the first row in CSV order. Example mappings:
  `ran -> run`, `paid -> pay`, `children -> child`, `mice -> mouse`,
  `went -> go`, `better -> good`, `api -> API`.
- `meta` keys: `source_url`, `source_license`, `built_at`, `row_count`,
  `schema_version` (`1`), `source_sha256` (SHA-256 of the CSV).

## Querying

Open the database read-only. Examples:

```sql
-- exact (case-insensitive) headword lookup
SELECT word, phonetic, translation, bnc, frq, collins, oxford, exchange
FROM entries
WHERE word_lower = lower(:word);

-- exact case-sensitive lookup
SELECT * FROM entries WHERE word = :word;

-- fall back to a lemma when the selected surface form is not a headword
SELECT e.*
FROM forms f
JOIN entries e ON e.word = f.word
WHERE f.form = :word;
```

For a Windows app that only reads the file, use a read-only SQLite connection
(for example `Mode=ReadOnly` with Microsoft.Data.Sqlite, or a `file:...?mode=ro`
URI). Do not create `-wal`/`-shm` sidecars next to the shipped artifact.

## Rebuild

Requirements: Python 3.10 or later, standard library only. No packages are
needed. The builder streams the CSV with the `csv` module and never loads the
whole file into memory.

```text
:: Download the CSV to a fresh OS temp directory outside the repo, build the
:: database plus manifest, then delete the downloaded CSV.
python -I tools/DictionaryBuilder/build_ecdict.py

:: Use an existing CSV (it does not need to live in the repository).
python -I tools/DictionaryBuilder/build_ecdict.py --csv C:\path\to\ecdict.csv

:: Reproducible timestamp; same CSV + same built_at + same SQLite version
:: produces byte-identical output.
python -I tools/DictionaryBuilder/build_ecdict.py --csv C:\path\to\ecdict.csv ^
  --built-at 2026-11-07T10:42:47Z
```

Defaults and behavior:

- Output: `assets/dictionary/dict-en-zh.sqlite`; manifest:
  `assets/dictionary/manifest.json`. Override with `--out` and `--manifest`;
  `--no-manifest` skips the manifest.
- With no `--csv`, the CSV is downloaded from the URL above into
  `%TEMP%\thanslator-ecdict-*` and removed after the build. `--keep-csv` keeps
  it; `--download-dir` uses a caller-supplied directory outside the repository.
- The script prints the CSV size/hash, entry/form/meta counts, skipped token
  statistics, database size/hash, and runs `PRAGMA integrity_check` before
  replacing the output file. It writes through a `.tmp` file and then renames.
- The builder is deterministic: it processes rows and form candidates in CSV
  order and resolves conflicts by a documented fixed priority. During this
  build, a second run with the same CSV, `--built-at`, and SQLite 3.49.1
  produced an identical 99,794,944-byte file with SHA-256
  `940c46ae8c94a205cdf109887f171721b8ee567cdbc9d0b36f714d083209240f`.
  Cross-version bit-for-bit reproducibility is not guaranteed because SQLite
  file layout can change between SQLite releases.

## Repository hygiene

The downloaded CSV is never written into the repository. The repository's
`.gitignore` contains `*.db`, so `dict-en-zh.sqlite` is ignored by normal Git
tracking. Do not commit the 66 MB CSV or the database to source history; ship
the database through the release/dist pipeline and regenerate it with the
builder when the upstream snapshot changes.
